## 5. THE SHELL PATCH I AM REQUESTING (one method, one signature)

**`window.sotto.dispatch` exists but cannot carry what `lazy-assets.js` sends.**

* `app/panel/lazy-assets.js` (S7's, 12 871 B, injected by the shell as part of
  `BOOTSTRAP_JS`) asks with TWO arguments:
  `window.sotto.dispatch('lazy-asset', { url: String(url) })`.
* `SottoHost.dispatch(self, wire)` (`sotto_webview.py:3426`) takes ONE argument — a JSON
  **string** — and does `json.loads(wire)`. Called with `'lazy-asset'`, `json.loads`
  raises and the ask dies in `BRIDGE_BAD_MESSAGE`.
* The handler ALREADY EXISTS: `'lazy-asset': self._lazy_asset` at `:3470`,
  `def _lazy_asset(self, payload)` at `:3571`. Only the wire shape is wrong.
* The fallback `window.pywebview.api.dispatch` is the same object with the same
  signature, and it only exists after the page finishes loading — so at
  document-created time (when the ask fires) there is no working path at all.

**The patch:** let `SottoHost.dispatch` accept the two-argument form and normalise it,
e.g. `if isinstance(wire, str) and len(args) > 1: wire = json.dumps({"kind": wire,
"payload": args[0]})` before the `json.loads`. Nothing else changes: the message map,
the handler, and every other caller are untouched.

**Why I did not just remove the five eager assets instead:** a cine or pd theme at startup
would lose its skin, because the shell serves an empty 200 for a deferred URL unless the
page has asked for the real bytes. The ask is the mechanism; it is the signature that is
broken.

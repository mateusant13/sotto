## 6. How per-process VRAM was measured - and why not `nvidia-smi`

Three paths, all in-process on this box:

| path | result |
|---|---|
| `nvidia-smi --query-compute-apps=pid,used_memory` | `Failed to initialize NVML: Unknown Error` from this box's shells; `used_memory` printed `[N/A]` in the Lead's session |
| `nvmlDeviceGetComputeRunningProcesses_v2` | **lists the pids** (33 of them) but returns `usedGpuMemory == 0` for every one |
| **PDH `GPU Process Memory`** (the one that works) | `win32pdh` wildcard query + `GetFormattedCounterArray` -> `{instance_name: bytes}`; the instance name carries the pid; agrees with PowerShell `Get-Counter` on the same object |

Two quirks cost real time and are recorded so the next lane does not rediscover them: the
counter path carries **one** backslash before the object and **one** before the counter
name (`\GPU Process Memory(*)\Dedicated Usage`), and the query must be collected **twice
with a settle between** - a single collect answers "Nao ha dados a serem retornados".

**Caveat, stated rather than hidden:** PDH `Dedicated Usage` is a per-process allocation
figure; NVML `used` is a device-wide counter. They are not the same measure and do not
sum to each other (6 599.9 vs 5 086 MiB in the same window). Both are reported by the
instrument; neither is described as the other.

## 8. What is OUT OF REACH, and why (the honest half)

**Reusing a VRAM copy held by another process is impossible without that process's
cooperation.** This is a property of CUDA, not a gap in effort:

* A CUDA allocation is **private to the process that made it**. There is no name,
  offset or handle by which an outside process can ask for somebody else's tensor.
* The only mechanism that shares one across processes is **CUDA IPC**, and it is
  cooperative by construction: the owner calls `cudaIpcGetMemHandle()` on its
  allocation and hands the resulting handle to the other side over a channel only the
  owner can create; the receiver calls `cudaIpcOpenMemHandle()` with that handle.
* Neither call can be made **by** a third party. We cannot reach into
  `NVIDIA Overlay.exe` and ask it for a handle it never exported, and we cannot
  enumerate another process's VRAM to look for one - allocations are not nameable
  from outside. WDDM hides the per-process figure anyway: NVML lists the pids and
  reports `usedGpuMemory == 0` for every one.

So the reachable half is **detection**, and it is built: if the same model is already
resident in another process, Sotto now prints that, loudly, before loading anything.
The reuse itself would require the other process to export a handle. On this box the
only process holding our model is the owner's own worker, which is ours - so there is
nobody to ask.

What would make it reachable, for the record: an owner side that called
`cudaIpcGetMemHandle()` on its CUDA allocations and published the handles (a named pipe,
a shared file) plus a lookup keyed on model identity. Nothing in this repo does that, and
nothing outside it can be made to do it.

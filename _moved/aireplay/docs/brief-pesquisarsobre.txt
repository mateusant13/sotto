1. Quanto tempo para indexar 1.000 vídeos?
Você tem:

1.000 × 300 MB = 300.000 MB ≈ 300 GB

O primeiro gargalo será o HDD.

Um HDD comum pode entregar aproximadamente 100–200 MB/s de leitura sequencial, dependendo do modelo e da posição dos dados.

Só para ler os 300 GB:

100 MB/s → ~50 minutos

150 MB/s → ~33 minutos

200 MB/s → ~25 minutos

Mas não significa que a indexação vai terminar em 25–50 minutos.

Você também precisa:

abrir o vídeo;

decodificar o H.264/H.265/AV1 etc.;

selecionar os frames;

redimensionar os frames;

passar pelo EmbeddingGemma;

gerar os embeddings;

salvar o índice.

Então eu estimaria, de forma prática:

Hardware	Estimativa para 1.000 vídeos
CPU comum + HDD	algumas horas até >10 h
GPU razoável + HDD	~1–4 h
GPU forte + HDD	provavelmente limitado pelo HDD/decodificação
SSD + GPU	pode cair bastante

Eu não projetaria o sistema esperando um número exato sem benchmark, porque o codec, resolução, duração e GPU fazem uma diferença enorme.

A boa notícia é que 300 GB não é uma quantidade absurda para indexar.

processos isolados;

sem ficar tão exposto aos problemas clássicos de memória do C++.

Para um programa que vai ficar rodando durante horas enquanto a pessoa joga, isso é especialmente valioso.

Onde eu NÃO tentaria usar Rust puro
Principalmente nas APIs NVIDIA/Windows mais específicas.
